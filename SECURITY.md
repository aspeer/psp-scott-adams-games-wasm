# Security Policy

This is the security policy for the Scott Adams Adventure Terminal
demonstration application.

This policy was updated on 2026-09-26.

## Reporting a Security Vulnerability

Please report security vulnerabilities via GitHub private vulnerability
reporting for this repository:

https://github.com/aspeer/psp-scott-adams-games-wasm/security/advisories/new

GitHub private vulnerability reporting is enabled for this repository and is
the preferred reporting point.

If you cannot use GitHub, report the issue privately by email to the current
project maintainer:

Andrew Speer <andrew.speer@isolutions.com.au>

Please do not report security vulnerabilities through public GitHub issues,
public pull requests, social media, chat channels, or other public forums.

Include enough detail to reproduce and assess the issue, including the affected
revision or deployed application, reproduction steps, relevant configuration or
request details, whether the issue is known to be actively exploited, and
whether you want public credit. Do not include credentials, tokens, private
keys, personal data, or other sensitive information unless it is strictly
necessary and safe to share.

## Supported Versions

Security fixes are normally made against the current deployment and the latest
version on the main branch of the
[GitHub repository](https://github.com/aspeer/psp-scott-adams-games-wasm).
Older revisions are not routinely supported.

## Handling and Disclosure

The maintainer will aim to acknowledge security reports as soon as practical,
investigate the report, and coordinate a fix and public disclosure where
appropriate. Exact response times cannot be guaranteed.

Please do not publicly disclose the vulnerability, exploit details, patches,
or mitigation advice until a coordinated disclosure date has passed or the
issue has been made public by the maintainer.

## Scope

This policy applies to vulnerabilities in the demonstration application itself.
Vulnerabilities in WebDyne, ZeroPerl, Cloudflare services, xterm.js, or other
dependencies should be reported to their respective maintainers. Copyright and
licensing questions concerning the bundled games are not security reports.
General bugs, feature requests, and documentation issues should use the normal
GitHub issue tracker.
